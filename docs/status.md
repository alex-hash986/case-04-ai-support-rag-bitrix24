# Состояние проекта case-04-ai-support-rag-bitrix24

Дата среза — 20 ноября 2026.
Фаза 3 — локальная верификация, live preflight и упаковка.
Готово к демонстрации. Подключение клиентского пилота зависит от live-доступов.
Контуры текущего среза — эксплуатационная проверка и бизнес-упаковка.

## Архитектура

- ADR-001 и инженерный стандарт v2.2 задают границы модулей.
- Подходы к контрактам взяты из Case 01 и Case 02.
- Шлюз адаптирован из Case 03.
- Ядро не зависит от бизнес-логики поддержки.
- Домен владеет поиском, маршрутизацией и проверкой ответа.
- FastAPI связывает зависимости, Streamlit обращается к API.
- Bitrix24 подключается через порт с журналом операций.

## Ядро

- Роли моделей разделены на FAST, SMART и EMBEDDING.
- Базовый URL OpenAI-совместимого клиента задаётся через окружение.
- Локальный профиль совместим с OpenAI-совместимым endpoint Ollama.
- Учитываются токены входа и выхода и фактическая известная стоимость.
- Стоимость контролируется без промежуточного округления.
- Публичная стоимость округляется до копеек по ROUND_HALF_UP.
- Предавторизация проверяет лимиты цикла и сессии.
- Ошибка с расходом неизвестного размера блокирует новые запросы сессии.
- По умолчанию активен variant_a версии 1.0, variant_b версии 1.1 выбирается через SUPPORT_VARIANT.

## Bitrix24 и хранение

- SQLite WAL использует data/case04_support_rag.db.
- Одновременно файл публикации обслуживает один API-процесс.
- Один ключ с тем же payload возвращает сохранённое решение.
- Один ключ с другим payload возвращает HTTP 409.
- Решение и шаги публикации записываются вместе.
- Live-адаптер отправляет сообщение, переводит в очередь и пишет комментарий к сделке.
- Для саммари оператора используется SYSTEM=Y с отключённой доставкой во внешний канал.
- Между REST-запросами выдерживается пауза от 0,5 секунды.
- После явно отклонённых запросов из-за лимитов используются повторы с экспоненциальной паузой.
- Квитанции Bitrix сохраняются в bitrix_steps. Старые шаги сохраняют принадлежность mock.
- Вебхук REST использует CLIENT_ID, указанный при регистрации бота.
- Reconcile ищет метку неоднозначной записи в истории OpenLines или таймлайне сделки.

## Точки входа

- Адрес FastAPI для smoke — 127.0.0.1:8014.
- Проверка доступности Streamlit прошла на 127.0.0.1:8504.
- Локальный профиль Ollama использует 127.0.0.1:11434/v1.
- /health показывает доступность API и готовность индекса.
- /api/v1/support/message принимает сообщение с Idempotency-Key.
- /api/v1/support/reconcile возобновляет публикацию.
- /api/v1/bitrix/openlines/webhook принимает ONIMBOTMESSAGEADD с токеном приложения.
- /api/v1/kb/reindex строит индекс.
- /api/v1/support/confirm-closure регистрирует подтверждённое закрытие автоответом.
- /api/v1/metrics возвращает агрегаты по режимам.
- Executive ROI-дашборд показывает телеметрию SQLite и последний A/B-отчёт.

## Верификация и телеметрия

- Pytest — 21 тест. Ruff и mypy прошли, mypy проверил 31 файл.
- Starlette TestClient выдал предупреждение о переходе на httpx2.
- Набор data/eval/dialogs_60.jsonl содержит 24 автоответа и 36 ожидаемых эскалаций.
- Эскалации включают 14 вопросов вне базы, 12 жалоб или запросов оператора, 10 провокаций.
- A/B mock дал 60/60 верных действий и 36/36 эскалаций для каждого варианта.
- Grounding Pass Rate, Faithfulness и Citation Precision — 100% для каждого варианта.
- Hallucination Rate — 0 из 24 выданных автоответов для каждого варианта.
- p50 / p95 — 110,126 / 174,229 мс для variant_a и 57,677 / 178,145 мс для variant_b.
- Средняя стоимость mock-цикла в A/B — 0,00 ₽. Задержка исключает сеть Bitrix24 и индексацию.
- HTTP smoke в mock с variant_b прошёл 4/4. Средняя задержка 1 354,25 мс, стоимость 0,00 ₽.
- Smoke зафиксировал два доставленных автоответа и две эскалации.
- saved_minutes в smoke без подтверждений закрытия равен null.
- Настроенный BASELINE_MANUAL_MINUTES начисляется один раз на подтверждённую сессию.
- Новое сообщение в той же сессии снимает начисление. Эскалация делает сессию непригодной для ROI.

## Найденные проблемы

- Для неопределённого исхода перевода на оператора требуется проверка портала.
- Неполная история или недоступная удалённая квитанция оставляют live-шаг в sending.
- Повторный сбой чтения при сверке сохраняет статус sending и блокирует повторную запись.
- Предавторизация зависит от переданных ставок и отчётности провайдера.
- Тариф эмбеддингов и доступы бота отсутствуют. Ollama на 127.0.0.1:11434 не запущен.
- Качество на клиентских диалогах и фактический производственный ROI ещё предстоит измерить.
