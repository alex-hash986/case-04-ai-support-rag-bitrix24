# Контракты Фаз 1 и 2

FastAPI привязан к 127.0.0.1:8014, Streamlit к 127.0.0.1:8504.
SQLite WAL хранится по пути data/case04_support_rag.db.

## DTO и API

Все DTO запрещают лишние поля. ChatMessageIn содержит session_id, dialog_id,
user_id, необязательный положительный deal_id, channel, message_text и history
из пар role/text. SupportDecisionOut содержит действие, причину, уверенность,
ответ, цитаты, саммари, статус Bitrix, стоимость, задержку и трассировку поиска.
RetrievedChunk содержит doc_id, section, chunk_id, text и score в диапазоне 0–1.
Клиенту OpenLines передаётся только проверенный текст и список источников.

- GET /health проверяет SQLite.
- POST /api/v1/support/message требует Idempotency-Key. Совпадающий payload
  получает последний сохранённый результат, другой payload получает 409.
- POST /api/v1/support/reconcile повторяет незавершённые шаги публикации.
- POST /api/v1/kb/reindex перестраивает снимок индекса целиком.
- GET /api/v1/metrics агрегирует сохранённые решения по режимам LLM mock и live.
- POST /api/v1/bitrix/openlines/webhook принимает ONIMBOTMESSAGEADD в JSON
  или form-urlencoded. Токен берётся из auth.application_token. Ключ запроса
  вычисляется из DIALOG_ID и MESSAGE_ID. Системные сообщения и события ботов пропускаются.
- POST /api/v1/support/confirm-closure принимает {request_id} и X-Bitrix-App-Token.
  Отправитель подтверждает фактическое закрытие. Учитывается последнее
  доставленное решение сессии, если в сессии отсутствовала эскалация.

## Хранилище и порт Bitrix

cycles хранит ключ, хэш запроса, сессию, результат и телеметрию.
bitrix_steps хранит последовательность операций, payload, статус и попытки.
mock_receipts хранит квитанции по устойчивому идентификатору операции.
embedding_cache хранит векторы по адресу провайдера, модели и содержимому.
Один API-процесс владеет файлом публикации. Асинхронные операции записи,
reconcile и reindex сериализуются в пределах процесса. Решение с журналом
шагов фиксируется одной транзакцией до отправки. Мок повторно использует
квитанцию по operation_id, в том числе при сбое после вызова до фиксации шага.

## Решение и бюджет

Явная эскалация проверяется до поиска. Слабая выдача блокирует генерацию.
Модель возвращает цитируемые идентификаторы и извлечённые дословно фразы.
Ответ должен состоять из полных предложений из указанных источников.
Предавторизация ограничивает расходы цикла и сессии до сетевого запроса.
Неизвестная стоимость после ошибки провайдера блокирует дальнейшие вызовы
этой сессии. Переиндексация имеет отдельный накопительный бюджет цикла.
В режиме variant_b разрешены фиксированное приветствие и маркированный список
полных предложений. Числа и сопровождающие условия проверяются вместе с текстом.
saved_minutes фиксирует BASELINE_MANUAL_MINUTES при подтверждении закрытия.
Любое новое сообщение той же сессии снимает ранее начисленные минуты.
Без подтверждений или настроенного базового времени агрегат равен null.

## Live Bitrix24

bitrix_steps хранит режим адаптера и квитанцию операции. Для старых строк
без указания режима используется mock. Шаги live выполняются в порядке журнала.
Между REST-запросами выдерживается минимум 0,5 с. Явный отказ из-за лимита
и ошибки установки соединения повторяются с экспоненциальной задержкой.
Для неоднозначной записи reconcile ищет метку операции в истории чата
или комментариях сделки. При отсутствии достоверной квитанции шаг остаётся
в состоянии sending. Для двусмысленного результата перевода требуется сверка
состояния сессии администратором портала.
